## What the run found

Four defects in the adoption path, none in the pipeline itself. All filed.

1. **"Use this template" cannot target a subfolder.** The docs pointed at `templates/records/` and `templates/site/`; GitHub templates are whole repos. Fixed in this PR by creating `uvularia-records-template` and `uvularia-site-template` (lentago/.github#205) and pointing the docs at them; automatic sync is lentago/uvularia#28.
2. **Duplicate obligation ids pass validation.** A missed step 4 produced a doubled board row and nothing failed. lentago/uvularia#29.
3. **The intake door keys on a label the template never creates.** lentago/uvularia#31.
4. **The intake workflow cannot open its PR under GitHub's default Actions permissions.** It pushes the branch and dies. lentago/uvularia#30. Until fixed, `ADOPTION.md` carries a Heads up with the one-time setting and the by-hand fallback.

Two observations, not defects: a board row shows the *current* standing of a rule, so a timely notice retires the red that late ones earned — the history stays in the records and receipts but is not on the board (a Phase 1 question); and the site's first deploy can race the vault's Pages, which the schedule heals within 30 minutes.
